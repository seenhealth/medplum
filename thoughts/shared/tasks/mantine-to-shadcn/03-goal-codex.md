# Codex Goals for the `medplum-shadcn` migration

Written with the `codex-goal-writer` contract: outcome · verification surface · constraints · boundaries · iteration policy · blocked stop condition. The task passes the decision gate (durable objective, evidence-based finish line in the ledger/tests/stories, uncertain multi-round path), so Goals are the right tool. Lifecycle: `/goal`, `/goal pause`, `/goal resume`, `/goal clear`.

Decisions baked in (confirmed by the user 2026-09-03, see plan §12): new private repo `seenhealth/medplum-shadcn`, Radix base, Tailwind v4, GitHub-registry distribution `seenhealth/medplum-shadcn/<item>`, v1 = Phases 0–7 (120 dirs, 1,097 test cases, 283 stories; Phase 8 deferred), presentational API rewritten as shadcn composition with behavior props preserved (D5), upstream pin `medplum/medplum@0e501215d` (`@medplum/react@5.1.36`, the fork's `cursor/upstream-main-5-1-36-a44b`). Paths refer to the plan in `02-plan-shadcn-registry-migration.md` and the appendices in this folder.

## Goal A — Phase 0: foundation and golden example (run first, in the architect session)

```text
/goal Stand up the medplum-shadcn repository so that human-name-display and human-name-input are fully ported from @medplum/react 5.1.36 (upstream medplum/medplum@0e501215d) to shadcn/ui on Radix + Tailwind v4 and pass all six verification layers, verified by: `pnpm test` running the upstream HumanNameDisplay/HumanNameInput test files unchanged except the render import and reporting 6/6 cases green; `pnpm test:stories` rendering medplum-humannamedisplay--basic, medplum-humannameinput--basic, --disabled and --partially-disabled in Chromium; `pnpm registry:build --check` passing and `pnpm registry:smoke human-name-input` installing the item into a scratch Vite app via `shadcn add` with `tsc --noEmit` clean; `pnpm parity human-name-input` reporting zero undocumented prop deltas; `pnpm compare:stories human-name-input` producing artifacts/<storyId>.png for all four story IDs; and MIGRATION_STATUS.md generated from ledger.json showing 2/125 components done — while preserving upstream behavior exactly (logic copied verbatim, only imports/JSX/CSS changed, data-testid/name/placeholder/label/role contract intact, behavior props unchanged and presentational props expressed as shadcn composition per plan D5 with form-section, panel and modal as the reference implementations, no new behaviors or features, SPDX header plus Apache §4(b) notice on every ported file). Use only: the plan and appendices in thoughts/shared/tasks/mantine-to-shadcn/, a read-only sparse checkout of upstream packages/react/src and packages/storybook/.storybook at the pinned SHA under upstream/ (never the seenhealth/medplum fork checkout), published @medplum/core, @medplum/react-hooks, @medplum/fhirtypes, @medplum/mock, @medplum/definitions at 5.1.36, the official shadcn registry items listed in WU-00, pnpm, Vite, Vitest, Storybook 10, Playwright, Biome. Deliver in order WU-00 → WU-01 → WU-02 → WU-03 → WU-04 and write docs/translation-guide.md and docs/porting-rules.md from plan §4–§5 as you go. Between iterations, record in ledger.json what was ported, which layer is red and why, and the next smallest action; commit per work unit and open one draft PR per WU with the ledger row and test summary in the body. If a layer cannot be made green (a primitive is missing, a test asserts Mantine-only DOM, the CLI transformer rewrites an import unexpectedly), stop with: the failing command output, the attempted alternatives, the exact primitive or decision needed (name D0–D11 where relevant), and what would unlock progress.
```

## Goal B — Program: migrate the 120 v1 component directories (architect session dispatching executors)

```text
/goal Deliver medplum-shadcn v0.1.0+medplum.5.1.36: every one of the 120 v1 component directories in @medplum/react 5.1.36 (appendix A minus the deferred Phase 8 dirs AppShell, NotificationIcon, auth, GoogleButton, chat) ported to shadcn/ui items following plan §8 phases 0–7 and installable via `pnpm dlx shadcn@latest add seenhealth/medplum-shadcn/<item>`, verified by MIGRATION_STATUS.md (generated from ledger.json) showing 120/120 rows with L1–L6 green: ≥1,042 of the 1,097 upstream test cases passing unmodified or with documented selector-only or composition-render-call edits and every skip justified as a Mantine-DOM-only assertion, 283/283 upstream stories rendering under their original Storybook IDs (appendix B) in `pnpm test:stories`, `pnpm registry:build --check` and `pnpm registry:smoke --all` green in CI, `pnpm parity --all` with every prop delta listed in docs/migration/<item>.md, `pnpm check:no-mantine` and `pnpm check:no-css-modules` empty, and side-by-side artifacts reviewed for every story ID — while preserving upstream behavior exactly (plan §4 rules), keeping exported names and behavior props unchanged and expressing presentational API as shadcn composition (D5), depending on rather than vendoring @medplum/core and @medplum/react-hooks (D9), using @tabler/icons-react (D7) and shadcn semantic tokens only (D8). Use only the repository seenhealth/medplum-shadcn, the read-only upstream/ checkout at upstream.lock, the plan and appendices, and executor agents (Grok 4.6 fast for leaf work units, GPT 5.6 sol medium fast for WU-15, WU-20, WU-21, WU-22, WU-24) each given the plan §6 work-unit prompt with one WU; run WUs within a phase in parallel and phases in dependency order (§3.4). Between iterations, audit each executor PR against plan §9 (upstream diff shows only import/JSX/className hunks, tests and stories diff only in allowed ways, ledger row complete), merge or send back with the failing layer named, update the translation guide when a new Mantine pattern appears, and choose the next unblocked WU. If a WU stalls twice on the same blocker, or an executor cannot reach ≥95% on a component after porting the primitive it needs, stop and report: the component, the failing test names and outputs, the Mantine behavior with no shadcn counterpart, the options (custom registry:ui primitive, documented API delta, defer to a later phase) and which decision D0–D11 or user input would unlock progress; a budget limit is a blocker, not completion.
```

## Goal C — Executor work-unit template (fill the brackets; one per WU)

```text
/goal Port [Dir list for WU-xx] from @medplum/react 5.1.36 (upstream/packages/react/src at upstream.lock) to shadcn/ui items in seenhealth/medplum-shadcn, verified by `pnpm test [items]` reporting [N]/[N] upstream test cases green with every skip recorded in ledger.json as Mantine-DOM-only, `pnpm test:stories --filter [items]` rendering [story IDs from appendix B], `pnpm registry:build --check`, `pnpm registry:smoke [items]`, `pnpm parity [items]` with every delta written to docs/migration/[item].md, `pnpm typecheck`, `pnpm lint`, `pnpm check:no-mantine`, and `pnpm compare:stories [items]` producing artifacts for each story ID — while copying upstream logic verbatim (only imports, JSX and CSS change), keeping data-testid/name/placeholder/label/role/text contracts and every behavior prop, expressing presentational props as shadcn composition sub-components per docs/translation-guide.md, adding no behaviors, features, comments or logic refactors, and keeping the SPDX header plus the Apache §4(b) notice line. Use only docs/translation-guide.md, docs/porting-rules.md, the golden example src/components/medplum/human-name-input.*, the upstream/ checkout, and the shadcn primitives already under src/components/ui (import them via @/components/ui/*, never radix-ui or cmdk directly). Between iterations, run the failing layer's command, fix the smallest thing, and update ledger.json with tests passing/skipped, stories passing and the next action; commit per item and open a draft PR "port([item]): …" whose body pastes the ledger row and test summary. If a behavior cannot be reproduced with the available primitives or a test asserts Mantine-only DOM, stop with the failing test names and output, what you tried, the primitive or decision needed, and mark the item blocked in ledger.json instead of skipping or rewriting the test.
```

## Notes for whoever pastes these

- Goal A is the only one that should be active in a thread at a time; run it before dispatching any executor.
- Goal B's numeric floor (1,042) is 95% of the 1,097 v1 test cases; raise it if Phases 0–2 come in higher than expected.
- Goal A cannot start until `seenhealth/medplum-shadcn` exists and the agent environment can push to it.
